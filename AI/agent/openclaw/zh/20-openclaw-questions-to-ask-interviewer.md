# OpenClaw 面试反问清单

## 使用说明

- 这份不是让你机械背诵，而是让你在面试结尾时显得更成熟、更有判断力。
- 反问的目的，不是“把时间撑满”，而是体现你真的理解 AI Agent 系统、工程化落地和团队协作。
- 最好根据面试官身份选问题：
  - 技术面试官：偏架构、工程、协作、技术债。
  - 业务面试官：偏场景、价值、指标、优先级。
  - 主管/负责人：偏团队方向、角色期待、成长空间。

## 一条原则

好的反问，应该同时满足三点：

- 能体现你前面确实认真听了面试内容。
- 能体现你理解岗位真正难点。
- 能帮你判断这个岗位值不值得去。

## 一、最通用的高质量反问

### 1. 这个岗位当前最核心的挑战是什么？

为什么好：

- 能让你快速知道岗位到底是“建设期”还是“救火期”。
- 能体现你不只关心做什么，还关心难点是什么。

如果对方回答后，你可以顺着追问：

- 这个挑战更多是技术问题、产品问题，还是协作问题？
- 目前团队已经尝试过哪些方案？

### 2. 你们希望这个岗位的人，在入职后 3 个月最先解决什么问题？

为什么好：

- 这是判断岗位预期最有效的问题之一。
- 能直接知道你入职后是做增量建设，还是先接旧系统。

### 3. 你们怎么定义这个岗位做得好？

为什么好：

- 这个问题能看出团队评价标准是否清晰。
- 也能判断这个岗位是以“交付速度”为主，还是“系统质量”为主。

可以听的关键词：

- 是否有明确业务指标
- 是否有工程指标
- 是否强调 owner 意识
- 是否强调跨团队协作

## 二、如果岗位偏 AI / Agent / 平台建设

### 4. 你们现在做 AI 相关系统，最大的落地难点是什么？

为什么好：

- 这能直接问到最真实的问题，而不是停留在“我们也在做 AI”这种表述上。
- 你可以听出他们卡在模型效果、工具接入、数据质量、权限安全，还是业务闭环。

### 5. 你们更关注 AI 系统的哪些指标？

你可以期待对方提到：

- 调用成功率
- 延迟
- 任务完成率
- 用户留存
- 误触发率
- 成本控制
- 人工兜底比例

为什么好：

- 很多团队会说在做 AI，但未必有清晰指标体系。
- 这个问题能帮你判断他们是“试验型团队”还是“工程化团队”。

### 6. 目前你们在 AI Agent 方向，更偏单体助手，还是多 Agent 协作？

为什么好：

- 这个问题能看出团队对系统复杂度的取舍。
- 也能顺带聊到上下文管理、工具编排和权限边界。

### 7. 如果涉及工具调用或自动化执行，你们现在是怎么做权限控制和风险兜底的？

为什么好：

- 这是很成熟的问题，尤其适合聊 Agent 系统。
- 能体现你意识到 AI 不只是“会回答”，还涉及真实执行风险。

### 8. 你们在长会话、记忆、上下文压缩这类问题上，有没有遇到比较典型的瓶颈？

为什么好：

- 这个问题能拉开与普通候选人的差距。
- 因为很多人只聊 prompt，不会聊长期 session 和上下文工程。

## 三、如果岗位偏前端 / 全栈 / 工程平台

### 9. 你们现在更强调快速交付，还是更强调系统抽象和长期可维护性？

为什么好：

- 能帮你判断团队节奏。
- 也能判断技术债是否可控。

### 10. 这个团队目前最大的工程效率瓶颈是什么？

你可以听对方是否提到：

- 需求变化快
- 代码历史包袱重
- 测试不完善
- 研发规范不足
- 发布链路复杂
- 跨团队依赖多

### 11. 你们平时做技术方案和代码评审，大概是什么机制？

为什么好：

- 这个问题非常实用。
- 它直接关系到你进组之后能不能在正确环境里成长。

## 四、如果面试官是技术负责人

### 12. 你希望这个岗位的人，半年后能成长成什么样？

为什么好：

- 可以判断这个团队是否真的愿意培养人。
- 也能看出岗位是否有明确成长路径。

### 13. 团队里优秀同学和普通同学，最大的差别通常体现在哪？

为什么好：

- 这个问题能让你听到负责人眼里的“高绩效画像”。
- 很适合判断团队文化和价值取向。

### 14. 你们更希望这个岗位的人偏执行、偏方案设计，还是偏 owner？

为什么好：

- 能快速知道岗位的真实角色定位。
- 避免入职后发现自己预期和岗位不匹配。

## 五、如果面试官是业务方或产品方

### 15. 这个方向今年最重要的业务目标是什么？

为什么好：

- 你能判断岗位价值是不是核心业务。
- 也能知道项目是长期建设还是阶段性尝试。

### 16. 从业务视角看，这个岗位产出最容易被认可的事情是什么？

为什么好：

- 这能帮助你理解业务方对“好结果”的定义。
- 也有助于你判断未来如何拿结果。

## 六、反问 OpenClaw/Agent 类项目时特别容易出彩的提法

如果你前面已经聊了 OpenClaw 这种项目，可以挑下面几种提法：

### 17. 你们当前在 AI Agent 这类系统里，更重视“能力上限”还是“稳定可控”？

这个问题好在：

- 能直接切入 Agent 系统的核心 trade-off。
- 很多团队会在效果、成本、稳定性之间做平衡。

### 18. 你们现在在多渠道接入或多端统一控制上，有没有比较棘手的问题？

这个问题好在：

- 能自然引出消息路由、session 设计、权限隔离和监控。
- 如果对方真的做过这类系统，会很愿意展开。

### 19. 你们更看重 Agent 的“自主性”，还是“可审计、可回放、可兜底”？

这个问题好在：

- 说明你理解真实生产环境里，能力不是唯一目标。
- 对方一旦展开，你就能听出他们是否真正做过落地系统。

## 七、不建议问的问题

### 1. 你们加班多吗？

不建议一上来直接问。  
如果真想了解，可以放到最后，换更职业的说法，比如：

> 团队目前整体节奏大概是什么样？需求高峰期和稳定期差异大吗？

### 2. 我进去以后多久能升职？

太早问会显得关注点失衡。  
更好的问法是：

> 这个岗位通常怎样的人会成长得比较快？

### 3. 你们技术栈具体是什么？

如果前面已经聊过，再重复问就比较弱。  
除非你是想继续深入某个点，比如：

> 你们在现有架构下，最近最想升级或重构的部分是什么？

## 八、结尾万能版反问模板

如果时间不多，你可以直接从下面挑一组：

### 组合 A：最稳妥

> 我想了解一下，这个岗位当前最核心的挑战是什么？  
> 另外，如果我加入的话，前 3 个月最希望我先解决什么问题？

### 组合 B：偏工程化

> 想请教一下，团队目前在工程效率或系统稳定性上，最大的瓶颈是什么？  
> 以及你们通常怎么做技术方案和代码评审？

### 组合 C：偏 AI / Agent

> 如果是 AI Agent 方向的话，你们当前最大的落地难点是什么？  
> 另外在权限控制、风险兜底和效果评估上，你们现在比较看重哪些指标？

## 九、你的目标不是问很多，而是问得准

建议一次问 2 到 3 个就够了。

优先顺序建议：

- 第一优先：岗位挑战
- 第二优先：3 个月预期
- 第三优先：团队怎么判断做得好

如果面的是 AI / Agent 相关岗位，再补一个：

- 落地难点 / 指标 / 风险控制

## 一句话总结

反问面试官最好的状态，不是“我还有几个问题”，而是：

> 我已经理解了岗位大致内容，现在我想进一步确认，这个岗位真正难的地方是什么、团队怎么做判断，以及我进去之后怎么才能做出价值。
