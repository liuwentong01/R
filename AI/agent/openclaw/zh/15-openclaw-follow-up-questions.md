# OpenClaw 面试追问与应答方向（对应 36 题）

## 使用说明

- 这份不是标准答案，而是“面试官接着会怎么追问”。
- 每题给出常见追问和建议回答方向，方便你做二次展开。
- 最适合和 `13-openclaw-classic-detailed-interview-qa.md`、`14-openclaw-2min-oral-outline.md` 配套使用。

## 一、整体认知与架构总览

### 01. OpenClaw 是什么？
- 常见追问：它更像产品、框架，还是平台？
- 应答方向：先回答“平台”，再补“对终端用户是产品，对开发者是框架和平台”。
- 常见追问：它和 AutoGPT、普通机器人框架差别在哪？
- 应答方向：强调真实消息渠道、控制平面、多 Agent、本地优先、长期运行能力。

### 02. 整体架构怎么讲？
- 常见追问：你觉得哪个模块最核心？
- 应答方向：优先回答 Gateway 和 Agent Runtime，前者负责控制，后者负责执行。
- 常见追问：如果删掉某一层，最先出问题的是哪部分？
- 应答方向：删 Gateway 会失去统一状态和安全入口；删 Runtime 就只剩通道，不再是 Agent 系统。

### 03. 为什么要 Gateway 中心化？
- 常见追问：中心化会不会导致单点问题？
- 应答方向：会，但这是一种有意识取舍，用单点换一致性和可控性。
- 常见追问：如果未来想分布式化，最难拆哪部分？
- 应答方向：session 状态、routing、presence、channel runtime 和 auth/approval 逻辑会最难拆。

### 04. 为什么同时用 WebSocket 和 HTTP？
- 常见追问：能不能只保留 HTTP + SSE？
- 应答方向：能覆盖部分场景，但双向控制、设备连接和实时事件推送不如 WS 自然。
- 常见追问：为什么不全走 WS？
- 应答方向：HTTP 更适合 webhook、health、OpenAI 兼容接口、静态资源托管。

### 05. 为什么强调 Local-first？
- 常见追问：Local-first 最大的收益是什么？
- 应答方向：隐私、控制权和与本地工作区/设备能力的深度融合。
- 常见追问：代价是什么？
- 应答方向：部署和运维更复杂，远程访问需要额外安全设计。

### 06. 为什么支持多 Agent？
- 常见追问：多 Agent 和多会话有什么区别？
- 应答方向：多会话是同一 Agent 的不同对话边界，多 Agent 是不同职责和权限边界。
- 常见追问：什么时候不需要多 Agent？
- 应答方向：单用户、单职责、低权限、上下文污染风险很低时，一个 Agent 足够。

## 二、Gateway、消息链路与路由

### 07. 消息完整链路
- 常见追问：链路里哪个步骤最容易出错？
- 应答方向：路由和 session 解析最关键，错了就会把消息送错上下文。
- 常见追问：链路里最适合做监控的是哪几层？
- 应答方向：入站通道、队列长度、Agent run 生命周期、出站失败率都要监控。

### 08. 最具体优先匹配
- 常见追问：如果两个同级规则都命中怎么办？
- 应答方向：配置顺序中的第一个获胜。
- 常见追问：为什么不做“最高分规则匹配”？
- 应答方向：规则层级已经表达了优先级，顺序更可预测，也更方便运维。

### 09. `dmPolicy` vs `dmScope`
- 常见追问：如果 `dmPolicy` 已经很严，还需要安全 `dmScope` 吗？
- 应答方向：需要，因为合法用户之间仍然可能上下文串话。
- 常见追问：你会怎么向非技术面试官解释这俩区别？
- 应答方向：一个管门禁，一个管座位。

### 10. `dmScope="main"` 风险
- 常见追问：那为什么系统还保留 `main`？
- 应答方向：因为单用户自用场景它很方便，跨渠道能共享上下文。
- 常见追问：如果一定要多用户共享上下文怎么办？
- 应答方向：那要显式承认这是共享助手，而不是私密 DM 助手，并重新设计隐私边界。

### 11. Gateway 是唯一数据源
- 常见追问：客户端直接读文件为什么不行？
- 应答方向：会读到不完整、过期或根本不在本机的数据。
- 常见追问：这种设计的代价是什么？
- 应答方向：所有客户端都依赖 Gateway 可用性，但换来状态一致。

### 12. 去重和防抖
- 常见追问：两者顺序为什么重要？
- 应答方向：通常先去重再防抖，先排除重复消息，再决定是否合并真实新消息。
- 常见追问：什么消息不适合防抖？
- 应答方向：媒体消息、控制命令、强时效消息通常不适合延迟合并。

## 三、Agent Runtime 与执行模型

### 13. Agent Loop
- 常见追问：什么是工具循环的结束条件？
- 应答方向：模型不再输出工具调用，而是产出最终纯文本回复。
- 常见追问：为什么这不只是“函数调用链”？
- 应答方向：因为涉及会话状态、流式事件、工具回填和多轮模型调用。

### 14. 两级队列
- 常见追问：如果不做 per-session 串行会怎样？
- 应答方向：上下文会乱序，工具结果归属混乱，session 一致性被破坏。
- 常见追问：如果不做全局并发限制会怎样？
- 应答方向：系统资源可能被大量会话同时打满，拖垮整体稳定性。

### 15. `collect` / `followup` / `steer`
- 常见追问：默认模式为什么是 `steer`？
- 应答方向：同回合 steering 是官方默认，能在不另起一轮的情况下把新消息注入当前运行，响应更快、更自然。
- 常见追问：`steer` 的风险是什么？
- 应答方向：可能打断原本将完成的工具链，逻辑复杂，也更容易让输出显得重复或跳转。

### 16. 系统提示动态组装
- 常见追问：动态组装最大的挑战是什么？
- 应答方向：信息太多时要控制膨胀，同时保持 prompt cache 稳定。
- 常见追问：为什么不把所有知识都注入？
- 应答方向：上下文不是越多越好，噪声和成本都会上升。

### 17. 子 Agent 用 `minimal`
- 常见追问：子 Agent 为什么不直接继承主 Agent 的所有记忆？
- 应答方向：局部任务不需要完整人格和长期上下文，继承太多会增加噪声。
- 常见追问：什么时候子 Agent 反而需要更多上下文？
- 应答方向：当子任务本身依赖主任务的大背景时，但也应该有选择地注入，而不是全量继承。

### 18. auth profile 轮换和 failover
- 常见追问：为什么先轮换 profile，再切 provider？
- 应答方向：先在同 provider 内恢复，语义和行为更稳定，切换代价更小。
- 常见追问：什么时候应该直接切 provider？
- 应答方向：profile 全挂、provider 整体异常、模型不可用或持续报错时。

### 19. Block Streaming vs Preview Streaming
- 常见追问：哪个更接近“真实输出”？
- 应答方向：Block Streaming，更适合最终正式消息。
- 常见追问：为什么不能所有平台都做 preview？
- 应答方向：不是所有平台都支持稳定编辑消息，且编辑频率和限制也不同。

## 四、Session、上下文与 Memory

### 20. Session 为什么重要？
- 常见追问：sessionKey 和 sessionId 有什么区别？
- 应答方向：sessionKey 是逻辑会话标识，sessionId 更像当前一次实体会话实例或存储标识。
- 常见追问：session 是业务概念还是存储概念？
- 应答方向：两者都有，但本质上首先是运行时控制边界。

### 21. Pruning vs Compaction
- 常见追问：为什么 pruning 优先剪工具结果？
- 应答方向：工具结果通常更大、更冗余，且比用户主线消息更适合裁剪。
- 常见追问：compaction 的风险是什么？
- 应答方向：摘要不可逆，细节会丢，所以压缩前要有记忆迁移或其它补救机制。

### 22. 记忆首先是文件
- 常见追问：这样会不会牺牲搜索性能？
- 应答方向：不会，因为文件是主数据，索引和向量库可以作为加速层。
- 常见追问：和纯数据库型记忆比，最大优势是什么？
- 应答方向：可解释、可编辑、可调试。

### 23. `memory-core` vs `memory-lancedb`
- 常见追问：默认为什么是 `memory-core`？
- 应答方向：因为它更基础、可解释性强、依赖更少，是稳定底座。
- 常见追问：什么时候更适合上 `memory-lancedb`？
- 应答方向：需要语义召回、自动捕获和更强长期记忆能力时。

### 24. 混合检索
- 常见追问：如果向量和 BM25 结果冲突怎么办？
- 应答方向：通过权重融合、重排序和阈值策略平衡，不是简单二选一。
- 常见追问：什么时候纯 BM25 更合适？
- 应答方向：精确实体、关键词、符号搜索时常更合适。

### 25. memory flush
- 常见追问：为什么不在 compaction 之后再写记忆？
- 应答方向：因为很多细节在 compaction 后已经被丢掉了。
- 常见追问：flush 最大风险是什么？
- 应答方向：写入过多无关内容，所以需要提示设计和写入边界控制。

### 26. Context Engine
- 常见追问：为什么不能把这部分逻辑写死在 SessionManager？
- 应答方向：因为上下文构造策略高度可变化，应该独立为可插拔层。
- 常见追问：自定义 Context Engine 的价值在哪里？
- 应答方向：可以实现更高级的检索、压缩、lossless 或 RAG 策略。

### 27. `ownsCompaction`
- 常见追问：如果自定义引擎实现了 `compact()` 但不设置 `ownsCompaction` 会怎样？
- 应答方向：仍可能走默认编排路径，语义不一定是“完全接管”，所以要清楚声明。
- 常见追问：这个字段为什么危险？
- 应答方向：因为它会改变系统压缩行为，一旦理解错，可能导致 compaction 逻辑缺失或重复。

## 五、插件系统、工具系统与安全

### 28. Plugin Everything
- 常见追问：插件化最大的代价是什么？
- 应答方向：加载、注册、边界管理和调试复杂度更高。
- 常见追问：为什么 OpenClaw 仍然值得这样做？
- 应答方向：因为能力种类多且变化快，不插件化核心会失控。

### 29. 插件导入边界
- 常见追问：为什么不能直接 import `src/**` 更快？
- 应答方向：短期方便，长期会把核心和插件绑死。
- 常见追问：如果插件确实需要新能力怎么办？
- 应答方向：应该先把能力提升到 Plugin SDK 的公共表面，而不是偷偷深引核心。

### 30. Hook 执行模式
- 常见追问：哪种 Hook 最危险？
- 应答方向：能改 prompt 或改工具参数的 modifying hooks 风险最高。
- 常见追问：哪种 Hook 最考验性能？
- 应答方向：同步热路径 hooks，因为每轮都可能经过且不能太慢。

### 31. Slot 系统
- 常见追问：为什么不是所有插件都用 slot？
- 应答方向：因为不是所有能力都要求唯一主实现，很多能力天然可以并行共存。
- 常见追问：slot 和 enable/disable 的关系是什么？
- 应答方向：slot 选主实现，enable/disable 控制插件是否参与系统，二者相关但不等价。

### 32. 工具系统的上下文感知工厂
- 常见追问：为什么不直接在工具内部做 if 判断？
- 应答方向：工厂层提前裁剪更清晰，也能避免把不可用工具暴露给模型。
- 常见追问：这种设计最大的收益是什么？
- 应答方向：工具可见性和权限控制可以在生成阶段就精细化。

### 33. Per-agent 工具权限和 Exec Approval
- 常见追问：为什么两层都要，不是一层就够？
- 应答方向：allow/deny 是静态权限边界，approval 是动态高风险动作控制。
- 常见追问：如果没有 approval，最危险的是什么？
- 应答方向：模型可能自动执行高权限命令，造成真实外部副作用。

### 34. 安全模型不只是 token
- 常见追问：你觉得最容易被忽视的安全点是什么？
- 应答方向：DM session 隔离、Origin 校验、工具权限和人类审批经常被低估。
- 常见追问：安全层太多会不会影响体验？
- 应答方向：会，但 AI assistant 接触真实渠道和设备，安全必须优先于“省一步点击”。

## 六、工程化、可维护性与系统设计总结

### 35. pnpm monorepo
- 常见追问：为什么不用多仓库？
- 应答方向：核心和插件边界虽然清晰，但仍然需要共享依赖、版本和构建基础设施。
- 常见追问：monorepo 最大风险是什么？
- 应答方向：边界不清时会变成超级大仓，所以 OpenClaw 才特别强调 import boundary 和公共 SDK。

### 36. 最值得学习的三个设计点
- 常见追问：你最认可哪一个？
- 应答方向：一般优先说 Gateway 控制平面，因为它把整个系统“立住了”。
- 常见追问：如果你复刻类似系统，最先会做哪一层？
- 应答方向：先做 Gateway + Session + Runtime 的稳定骨架，再逐步插件化能力。
