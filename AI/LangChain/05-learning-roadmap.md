# 05 - 学习路线与练手项目

## 学习目标

学完 LangChain 入门阶段后，应该能做到：

- 理解模型、提示词、消息、输出解析器的关系。
- 能用 LCEL 组合一个简单链路。
- 能搭建一个本地文档 RAG。
- 能写一个带工具调用的 Agent。
- 知道什么时候不用 Agent，什么时候该上 LangGraph。
- 能排查 RAG 和 Agent 的常见问题。

## 第 1 阶段：模型调用

目标：先跑通最小闭环。

需要掌握：

- Chat Model
- System/User/Assistant messages
- Prompt Template
- invoke / stream

练习：

1. 调用模型回答一个问题。
2. 加 system prompt 控制回答风格。
3. 用 Prompt Template 接收变量。
4. 尝试流式输出。

完成标准：

- 能解释 Chat Model 和普通 LLM 的区别。
- 能说明 system message 为什么比普通字符串拼接更清晰。

## 第 2 阶段：固定流程 Chain

目标：理解 Runnable 和 LCEL。

需要掌握：

- Runnable
- LCEL 管道
- Output Parser
- batch / stream

练习：

1. 写一个“输入主题 → 生成标题 → 生成摘要”的链路。
2. 写一个“输入文本 → 判断情绪 → 输出 JSON”的链路。
3. 给链路加结构化输出。

完成标准：

- 能用 `prompt | model | parser` 解释链路如何流转。
- 能判断固定流程是否比 Agent 更合适。

## 第 3 阶段：RAG

目标：做出第一个知识库问答。

需要掌握：

- Document
- Loader
- Splitter
- Embedding
- Vector Store
- Retriever
- Context Prompt

练习：

1. 用一个 Markdown 文件做问答。
2. 用一个目录下的多个文档做问答。
3. 返回答案时带来源。
4. 调整 chunk size，对比回答质量。
5. 对 20 个问题做手工评测。

完成标准：

- 能画出 RAG 的离线和在线链路。
- 能解释为什么“检索质量”比“Prompt 花活”更重要。
- 能排查“检索不到”和“检索到了但答错”的问题。

## 第 4 阶段：Tools

目标：让模型能够访问外部能力。

需要掌握：

- `@tool`
- 工具名称和描述
- 参数 schema
- 工具结果设计
- 错误处理

练习：

1. 写一个计算器工具。
2. 写一个查询天气的 mock 工具。
3. 写一个搜索本地文档的工具。
4. 写一个会返回错误的工具，并让模型优雅处理。

完成标准：

- 能说明工具描述为什么影响模型调用质量。
- 能区分“工具返回给模型看的内容”和“接口原始返回值”。

## 第 5 阶段：Agent

目标：理解工具调用循环。

需要掌握：

- create_agent
- Agent Loop
- State
- Runtime Context
- Middleware
- 最大迭代次数

练习：

1. 写一个能调用计算器和搜索工具的 Agent。
2. 让 Agent 根据问题决定是否检索文档。
3. 加最大工具调用次数。
4. 记录每次工具调用日志。
5. 给高风险工具加确认步骤。

完成标准：

- 能解释 Chain 和 Agent 的区别。
- 能说出 Agent 的不确定性来自哪里。
- 能设计一个边界清晰的工具集。

## 第 6 阶段：工程化

目标：让 Demo 具备上线前的基本形态。

需要掌握：

- tracing
- evals
- retry
- fallback
- rate limit
- token 成本
- prompt injection 防护
- 权限隔离

练习：

1. 为 RAG 准备一组评测问题。
2. 记录每次检索到的文档和最终答案。
3. 统计 token 消耗。
4. 对工具输入做权限校验。
5. 对检索文档中的恶意指令做隔离。

完成标准：

- 不只看“能不能回答”，还看“为什么这么回答”。
- 能复盘一次错误回答的完整链路。

## 推荐练手项目

### 项目 1：个人 Markdown 知识库问答

功能：

- 加载本地 Markdown 文件
- 建向量索引
- 输入问题返回答案
- 显示引用文件名

重点：

- Loader
- Splitter
- Retriever
- Prompt 约束

### 项目 2：前端面试助手

功能：

- 用户输入问题
- Agent 判断是概念题、代码题还是项目题
- 调用不同工具：知识库检索、代码示例生成、追问生成

重点：

- Tools
- Agent
- 输出结构化

### 项目 3：代码仓库问答助手

功能：

- 加载指定目录代码
- 按文件和函数切分
- 支持“这个函数做什么”“某个概念在哪里实现”
- 返回文件路径引用

重点：

- metadata
- 检索质量
- 引用来源

### 项目 4：研究报告助手

功能：

- 输入主题
- Agent 搜索资料
- 总结要点
- 输出结构化报告

重点：

- Agentic RAG
- 工具调用日志
- 结果引用
- 成本控制

## 常见误区

### 误区 1：一上来就用 Agent

很多任务固定流程就够了。Agent 适合不确定流程，不适合所有流程。

### 误区 2：RAG 等于向量库

向量库只是 RAG 的一部分。文档清洗、切分、metadata、检索策略、Prompt、评测都很重要。

### 误区 3：Prompt 能解决一切

Prompt 可以改善行为，但不能弥补糟糕的数据、错误的检索和混乱的工具设计。

### 误区 4：工具越多越强

工具越多，模型选择越困难，错误调用概率越高。工具集应该小而清晰。

### 误区 5：Demo 能跑就能上线

上线还需要观测、评测、权限、安全、成本、错误恢复和用户反馈闭环。

## 继续学习 LangGraph

当你完成 LangChain 入门后，如果遇到以下需求，就进入 LangGraph：

- 多步骤流程需要显式建模。
- 需要循环、分支和条件路由。
- 需要人工审批或人工修改中间状态。
- 需要任务暂停后恢复。
- 需要多个 Agent 协作。
- 需要长期运行且可追踪的工作流。
